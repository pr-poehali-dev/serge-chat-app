1. Из чего состоит проект

Сейчас мессенджер работает на платформе poehali.dev и состоит из четырёх частей. При переносе каждую нужно поставить на ваш сервер:

ЧастьЧто этоГде будет на вашем сервере
СайтReact-приложение, папка src. Собирается командой в папку dist (обычные HTML, JS, CSS)Обычная папка сайта
Серверная часть4 функции на Python 3: auth (вход, профиль), chats (чаты, настройки), send-message (отправка, пересылка, файлы), transcribe (голос в текст)Запускаются через готовую обёртку из папки deploy по адресам /api/auth, /api/chats и т. д.
База данныхPostgreSQL. Таблицы создаются файлами из папки db_migrationsPostgreSQL на сервере
ФайлыАватары, фото, голосовые, кружки, документы. Сейчас лежат в хранилище платформыПапка files на сервере
Что уже подготовлено в проекте В папке deploy лежат готовые файлы: запуск серверной части (app.py), конфиг веб-сервера (nginx.conf), автозапуск (trindelka.service), шаблон настроек (env.example), скрипт замены адресов (replace-api-urls.sh), скрипт переноса файлов (migrate-files.py) и вход для хостинга (passenger_wsgi.py). Сохранение файлов теперь умеет работать и в обычную папку на сервере: достаточно указать её в настройках.
Важно про проверку Обёртку серверной части я запускал у себя: она стартует и отвечает на проверочный адрес. Реальный сервер и панель ISPmanager я не видел, поэтому названия пунктов меню панели могут слегка отличаться у вашего хостера. Перед тем как переключать настоящих пользователей, сделайте пробный запуск и пройдите чек-лист из раздела 9.

3. Что подготовить заранее

  • Домен, например chat.example.ru. В DNS у регистратора добавьте запись A на IP-адрес вашего сервера. Изменения могут применяться до нескольких часов.
  • Доступ на сервер: IP, логин и пароль или SSH-ключ. Для Windows подойдёт программа PuTTY или встроенный ssh в PowerShell.
  • Почта для писем восстановления пароля: адрес SMTP-сервера, порт (465 или 587), логин и пароль. Для Яндекса и Gmail нужен специальный «пароль приложения», а не основной пароль.
  • Ключ OpenAI нужен только для расшифровки голосовых в текст. Без него мессенджер работает, а эта кнопка нет. С российских серверов доступ к OpenAI может быть закрыт.
  • Node.js версии 20 или новее нужен только для сборки сайта. Собрать можно на своём компьютере (nodejs.org) или прямо на VPS.
Пароли и секреты Придумывайте длинные пароли. Если в пароле есть символы @ : / # ?, в адресе базы их нужно закодировать (например, @ превращается в %40). Проще использовать пароль из латинских букв и цифр.

4. Как получить код проекта

Есть два способа, оба в меню проекта на poehali.dev:

  1. Скачать → Скачать код — архив со всем проектом. Распакуйте и загрузите на сервер.
  2. Скачать → Подключить GitHub — код уходит в ваш репозиторий. Это удобнее: на сервере код получают командой git clone, а потом обновляют командой git pull.

Подробности: docs.poehali.dev/deploy/github.

Что внутри архива src (сайт), backend (4 функции), db_migrations (таблицы базы), deploy (файлы для переноса), public (в том числе эта страница), package.json.

5. Часть 1. Перенос на VPS-сервер (Ubuntu 22.04 / 24.04)

Подойдёт сервер от 1 ядра и 2 ГБ памяти. Все команды выполняются на сервере под пользователем root. Где написано example.ru, подставьте свой домен.

  1. Подключитесь к серверу и обновите систему

    ssh root@IP_ВАШЕГО_СЕРВЕРА
apt update && apt upgrade -y

  2. Установите нужные программы

    apt install -y nginx postgresql postgresql-contrib python3 python3-venv python3-pip git curl ufw certbot python3-certbot-nginx
curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
apt install -y nodejs
node -v

    Последняя команда должна показать версию v20 или выше.

  3. Включите защиту: открыты только SSH, сайт и защищённый сайт

    ufw allow OpenSSH
ufw allow 'Nginx Full'
ufw --force enable
    Не пропускайте ufw allow OpenSSH до включения защиты, иначе вы потеряете доступ к серверу.

  4. Создайте папки и скачайте код

    Если код на GitHub (замените адрес на свой репозиторий):

    mkdir -p /var/www/trindelka/files
cd /var/www/trindelka
git clone https://github.com/ВАШ_АККАУНТ/ВАШ_РЕПОЗИТОРИЙ.git app

    Если у вас архив: загрузите его на сервер (программой WinSCP или FileZilla) и распакуйте так, чтобы получилась папка /var/www/trindelka/app с папками src, backend, deploy внутри.

  5. Создайте базу данных

    Придумайте пароль и вставьте его вместо ПРИДУМАЙТЕ_ПАРОЛЬ (латинские буквы и цифры).

    sudo -u postgres psql -c "CREATE USER trindelka WITH PASSWORD 'ПРИДУМАЙТЕ_ПАРОЛЬ';"
sudo -u postgres psql -c "CREATE DATABASE trindelka OWNER trindelka;"
sudo -u postgres psql -d trindelka -c "CREATE SCHEMA t_p64541051_serge_chat_app AUTHORIZATION trindelka;"
    Почему именно такое имя схемы Имя t_p64541051_serge_chat_app прописано и в коде, и в файлах таблиц. Оставьте его как есть, тогда ничего менять не придётся.

  6. Создайте таблицы

    Файлы применяются по порядку. Два файла с демонстрационными данными (V0003 и V0005) пропускаем: второй из них повторно добавляет те же тестовые аккаунты и на чистой базе даст ошибку «уже существует». Это вывод из чтения файлов, на пустой базе я их не прогонял.

    cd /var/www/trindelka/app
export DATABASE_URL="postgresql://trindelka:ПРИДУМАЙТЕ_ПАРОЛЬ@127.0.0.1:5432/trindelka"
for f in $(ls db_migrations/*.sql | grep -v -e V0003 -e V0005); do
  echo "== $f"
  psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -q -f "$f" || break
done

    Проверьте, что таблицы появились:

    psql "$DATABASE_URL" -c "\dt t_p64541051_serge_chat_app.*"

    В списке должны быть шесть таблиц: users, chats, chat_members, messages, message_reactions, chat_topics.

  7. Настройте адреса и соберите сайт

    Скрипт заменяет адреса функций poehali.dev на ваши /api/... и убирает служебные скрипты платформы из index.html.

    cd /var/www/trindelka/app
sh deploy/replace-api-urls.sh /api
npm ci
npm run build
ls dist

    В папке dist должны появиться index.html и папка assets. Сборка занимает 1–3 минуты.

    Метрика В index.html подключён счётчик Яндекс.Метрики платформы. Если он вам не нужен, удалите блок Yandex.Metrika counter до сборки. Если нужен ваш, замените номер счётчика.

  8. Установите серверную часть

    cd /var/www/trindelka
python3 -m venv venv
./venv/bin/pip install -r app/deploy/requirements.txt

  9. Создайте файл настроек

    Здесь хранятся пароли. Файл доступен только администратору.

    cp /var/www/trindelka/app/deploy/env.example /etc/trindelka.env
chmod 600 /etc/trindelka.env
nano /etc/trindelka.env

    Заполните значения. Что куда писать, показывает таблица в справочнике. Минимум для старта:

    DATABASE_URL=postgresql://trindelka:ПРИДУМАЙТЕ_ПАРОЛЬ@127.0.0.1:5432/trindelka
LOCAL_STORAGE_DIR=/var/www/trindelka/files
PUBLIC_FILES_URL=https://example.ru/files
SMTP_HOST=smtp.yandex.ru
SMTP_PORT=465
SMTP_USER=ваша_почта@yandex.ru
SMTP_PASSWORD=пароль_приложения
SMTP_FROM_EMAIL=ваша_почта@yandex.ru
OPENAI_API_KEY=

    Сохранить в nano: Ctrl+O, Enter, выйти: Ctrl+X.

    Без кавычек и пробелов вокруг знака «=». Строка PUBLIC_FILES_URL должна начинаться с https:// и вашего домена.

  10. Запустите серверную часть как службу

    chown -R www-data:www-data /var/www/trindelka/files
cp /var/www/trindelka/app/deploy/trindelka.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now trindelka
sleep 2
curl http://127.0.0.1:8000/api/health

    Ответ должен быть примерно такой: {"functions":["auth","chats","send-message","transcribe"],"status":"ok"}.

    Если ответа нет, смотрите журнал: journalctl -u trindelka -n 50 --no-pager.

  11. Подключите веб-сервер nginx

    cp /var/www/trindelka/app/deploy/nginx.conf /etc/nginx/sites-available/trindelka
sed -i 's/example.ru/ВАШ_ДОМЕН/g' /etc/nginx/sites-available/trindelka
ln -s /etc/nginx/sites-available/trindelka /etc/nginx/sites-enabled/trindelka
rm -f /etc/nginx/sites-enabled/default
nginx -t && systemctl reload nginx

    Команда nginx -t должна написать syntax is ok. Теперь сайт открывается по адресу http://ваш-домен.

  12. Включите HTTPS (бесплатный сертификат)

    certbot --nginx -d ВАШ_ДОМЕН -d www.ВАШ_ДОМЕН --redirect -m ваша_почта@example.ru --agree-tos -n

    Если у домена нет www, уберите часть -d www.ВАШ_ДОМЕН. Сертификат продлевается автоматически.

    После этого проверьте, что в /etc/trindelka.env адрес PUBLIC_FILES_URL начинается с https://, и перезапустите службу: systemctl restart trindelka.

  13. Откройте сайт и зарегистрируйтесь

    Зайдите на https://ваш-домен, нажмите «Регистрация» и создайте первый аккаунт. Затем пройдите чек-лист проверки.

6. Часть 2. Виртуальный хостинг с ISPmanager

На виртуальном хостинге нет прав администратора, поэтому нельзя поставить свои программы. Что можно сделать, зависит от тарифа. Сначала определите свой сценарий (см. раздел 2).

Общий порядок действий в панели Названия пунктов в ISPmanager 6: «Сайты» (WWW-домены), «Базы данных», «Менеджер файлов», «SSL-сертификаты». У разных хостеров они могут слегка отличаться. Если пункта нет, возможно, он не включён в тариф.

Шаг 0. Соберите сайт на своём компьютере (нужен для всех сценариев)

На хостинге Node.js, как правило, нет, поэтому сайт собирают дома и загружают готовую папку dist.

  1. Установите Node.js 20 или новее с сайта nodejs.org. На Windows ещё установите Git (git-scm.com): вместе с ним появится программа Git Bash, в которой работает команда sh.
  2. Откройте папку проекта в терминале (в Windows: Git Bash). Выполните команды из таблицы, выбрав свой сценарий:
СценарийКоманды
А: серверная часть на этом же хостингеsh deploy/replace-api-urls.sh /api
npm ci
npm run build
Б: серверная часть остаётся на poehali.devnpm ci
npm run build
(скрипт замены не запускать)
В: серверная часть на отдельном VPS по адресу https://api.example.rush deploy/replace-api-urls.sh https://api.example.ru/api
npm ci
npm run build

Результат: папка dist внутри проекта.

Шаг 1. Создайте сайт и сертификат

  1. «Сайты» → «Создать»: введите домен. Если домен куплен не у хостера, у регистратора пропишите NS-серверы хостера или A-запись на IP хостинга.
  2. Откройте созданный сайт → включите «SSL-сертификат» → выпустите бесплатный сертификат Let's Encrypt. Включите принудительное перенаправление на HTTPS.

Шаг 2. Загрузите сайт

  1. Откройте «Менеджер файлов», затем папку сайта. Обычно это /var/www/ИМЯ_ПОЛЬЗОВАТЕЛЯ/data/www/ваш-домен.
  2. Удалите оттуда стандартные файлы хостера (например, заглушку index.html).
  3. Загрузите содержимое папки dist (не саму папку): index.html, папку assets и остальное. Удобно загрузить zip-архивом и распаковать в менеджере файлов.
  4. Загрузите туда же файл public/install.html, если хотите, чтобы инструкция была доступна на сайте. Если нет, пропустите.

Шаг 3. Настройте открытие внутренних адресов

Адрес вида /reset-password (письмо восстановления пароля) физически не существует, его обрабатывает сам сайт. Нужно сказать веб-серверу открывать в этом случае index.html. Создайте в папке сайта файл .htaccess (точка в начале имени обязательна) с таким содержимым:

RewriteEngine On
RewriteBase /
RewriteCond %{REQUEST_URI} !^/api/
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-d
RewriteRule ^ /index.html [L]

<IfModule mod_expires.c>
  ExpiresActive On
  ExpiresByType image/svg+xml "access plus 1 month"
</IfModule>
Если после этого адрес /reset-password даёт ошибку 404 Значит, на вашем тарифе Apache не используется (работает только nginx), и .htaccess игнорируется. Тогда в настройках сайта найдите поле «Дополнительные директивы nginx» (или попросите поддержку добавить правило) и впишите: 
location / {
  try_files $uri $uri/ /index.html;
}

Сценарий А. Полный перенос на хостинг (нужны PostgreSQL и Python)

  1. Создайте базу PostgreSQL

    «Базы данных» → «Создать» → тип PostgreSQL. Запишите имя базы, пользователя, пароль и адрес сервера (чаще всего localhost, порт 5432). Обычно перед именами ставится префикс вашего аккаунта, например u123456_chat.

  2. Создайте таблицы

    Нужна схема с именем t_p64541051_serge_chat_app. Откройте веб-интерфейс базы (в панели рядом с базой есть кнопка «phpPgAdmin» или «Adminer»; если её нет, подключитесь по SSH, если тариф его даёт) и выполните по очереди:

    1. Запрос: CREATE SCHEMA t_p64541051_serge_chat_app;
    2. Содержимое файлов из папки db_migrations строго по порядку номеров: V0001, V0002, V0004, V0006, V0007, V0008, V0009, V0010, V0011, V0012, V0013, V0014. Файлы V0003 и V0005 (демо-данные) пропустите.

    Если у вас есть SSH, проще одной командой (подставьте свои данные):

    cd ~/trindelka-app
export DATABASE_URL="postgresql://ПОЛЬЗОВАТЕЛЬ:ПАРОЛЬ@localhost:5432/ИМЯ_БАЗЫ"
for f in $(ls db_migrations/*.sql | grep -v -e V0003 -e V0005); do psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -q -f "$f" || break; done

    Если хостинг не разрешает создавать схему, напишите в поддержку. Схему с таким именем создаст и выдаст вам права только администратор.

  3. Загрузите серверную часть

    Создайте в корне вашего аккаунта (вне папки сайта) папку trindelka-app и загрузите в неё папки backend и deploy. Сайт при этом остаётся в своей папке.

  4. Включите Python для сайта

    «Сайты» → ваш домен → «Изменить» → найдите режим работы Python (может называться «Python», «WSGI», «Passenger»). Если пункта нет, сценарий А на вашем тарифе недоступен, переходите к сценариям Б или В.

    Укажите:

    • каталог приложения: ~/trindelka-app/deploy
    • файл запуска: passenger_wsgi.py (он уже лежит в deploy)
    • версию Python: 3.9 или новее (подойдёт самая новая из списка)

  5. Установите зависимости

    Нужен SSH-доступ (в панели «Пользователи» → ваш пользователь → включить SSH). Команды:

    cd ~/trindelka-app
python3 -m venv venv
./venv/bin/pip install -r deploy/requirements.txt

    Если панель просит указать путь к интерпретатору, укажите ~/trindelka-app/venv/bin/python. Если SSH на тарифе недоступен, попросите поддержку установить пакеты из файла deploy/requirements.txt.

  6. Файл настроек

    Создайте файл ~/trindelka-app/deploy/.env (через менеджер файлов или SSH) и заполните по образцу deploy/env.example:

    DATABASE_URL=postgresql://ПОЛЬЗОВАТЕЛЬ:ПАРОЛЬ@localhost:5432/ИМЯ_БАЗЫ
LOCAL_STORAGE_DIR=/var/www/ИМЯ_ПОЛЬЗОВАТЕЛЯ/data/www/ваш-домен/files
PUBLIC_FILES_URL=https://ваш-домен/files
SMTP_HOST=smtp.yandex.ru
SMTP_PORT=465
SMTP_USER=ваша_почта@yandex.ru
SMTP_PASSWORD=пароль_приложения
SMTP_FROM_EMAIL=ваша_почта@yandex.ru
OPENAI_API_KEY=

    Затем в папке сайта создайте папку files и дайте ей права на запись (755, владелец ваш пользователь). Путь в LOCAL_STORAGE_DIR должен точно совпадать с реальным путём к этой папке: его видно в менеджере файлов.

    Закройте файл настроек от посторонних Файл .env лежит вне папки сайта и поэтому по адресу сайта не открывается. Не копируйте его в папку сайта. Права на него: 600.

  7. Перезапустите приложение и проверьте

    Нажмите в панели «Перезапустить» у Python-приложения (или создайте пустой файл ~/trindelka-app/deploy/tmp/restart.txt, это перезапускает Passenger). Откройте в браузере https://ваш-домен/api/health: должен появиться ответ status: ok.

    Если вместо этого открывается сайт или ошибка 404, значит запросы к /api/ не доходят до Python-приложения. Проверьте, что в .htaccess есть строка RewriteCond %{REQUEST_URI} !^/api/, и что приложение привязано именно к этому домену.

Сценарий Б. Сайт на хостинге, серверная часть остаётся на poehali.dev

Самый простой вариант: загружаете собранный сайт (шаги 0–3), больше ничего не нужно. Сайт будет обращаться к функциям и базе на poehali.dev, как сейчас.

Что нужно знать
  • Это не полный перенос: база, пользователи и файлы остаются на платформе.
  • Функции платформы ограничены количеством вызовов по вашему тарифу. Когда лимит исчерпан, сайт перестаёт работать (платформа отвечает 402 «Payment Required»). При моей последней проверке функции уже отвечали этой ошибкой. Если нужно больше вызовов, подписку продлевают на poehali.dev.
  • Письма восстановления пароля содержат ссылку на ваш новый домен: адрес берётся из заголовка запроса.

Сценарий В. Сайт на хостинге, серверная часть на отдельном VPS

  1. Сделайте часть 1 на VPS, но домен для него возьмите отдельный, например api.example.ru, и в конфиге nginx удалите блоки location /files/, location /assets/ и location / (оставьте только /api/), а в шаге с адресами сайта не собирайте сайт на VPS.
  2. Соберите сайт дома командой для сценария В (шаг 0) и загрузите на хостинг (шаги 1–3).
  3. Для файлов в /etc/trindelka.env укажите PUBLIC_FILES_URL=https://api.example.ru/files и в nginx оставьте блок location /files/.

Браузеру разрешено обращаться на другой адрес: серверная часть отдаёт все нужные заголовки.

7. Часть 3. VPS, на котором стоит ISPmanager

Если у вас VPS с root-доступом и уже установленной панелью, лучше не править конфигурацию nginx вручную: панель перезапишет её. Домен и сертификат ведите через панель, а серверную часть запускайте отдельной службой.

  1. Сайт и сертификат в панели

    «Сайты» → «Создать» → ваш домен. Затем выпустите сертификат Let's Encrypt и включите перенаправление на HTTPS.

  2. База PostgreSQL

    Если PostgreSQL ещё не стоит, включите его в «Настройки → Возможности» (название пункта зависит от версии). Затем «Базы данных» → «Создать» → PostgreSQL. После этого выполните шаги 5–6 из части 1, подставив данные вашей базы.

  3. Код, сборка, серверная часть

    Выполните шаги 4, 7, 8, 9 и 10 из части 1 по SSH. Папку приложения можно оставить /var/www/trindelka. Файлы лучше хранить внутри папки сайта, например /var/www/ИМЯ_ПОЛЬЗОВАТЕЛЯ/data/www/ваш-домен/files (и такой же путь в LOCAL_STORAGE_DIR), чтобы они отдавались как обычные файлы сайта.

  4. Положите собранный сайт в папку сайта

    cp -r /var/www/trindelka/app/dist/. /var/www/ИМЯ_ПОЛЬЗОВАТЕЛЯ/data/www/ваш-домен/
chown -R ИМЯ_ПОЛЬЗОВАТЕЛЯ: /var/www/ИМЯ_ПОЛЬЗОВАТЕЛЯ/data/www/ваш-домен

  5. Подключите /api через панель

    В настройках сайта найдите «Дополнительные директивы nginx» (или «Конфигурационные файлы nginx» у сайта) и добавьте:

    location /api/ {
  proxy_pass http://127.0.0.1:8000;
  proxy_set_header Host $host;
  proxy_set_header X-Real-IP $remote_addr;
  proxy_set_header X-Forwarded-Proto $scheme;
  proxy_read_timeout 90s;
}
client_max_body_size 25m;
location / {
  try_files $uri $uri/ /index.html;
}

    Сохраните: панель сама проверит и перезагрузит конфигурацию. Если панель пишет, что location / уже есть, уберите последний блок и оставьте только /api/, а открытие внутренних адресов включите в настройках сайта (режим «Обработчик» → «Статика», либо через файл .htaccess из части 2, шаг 3).

8. Перенос существующих пользователей, переписки и файлов

Шаги выше создают чистый мессенджер без пользователей. Если нужно сохранить уже зарегистрированных людей, их переписку и загруженные файлы, нужны ещё два действия.

8.1. Перенос данных базы

В таблицах лежат адреса почты, хеши паролей и сообщения живых людей, поэтому готового файла выгрузки в проекте нет, и класть его туда нельзя: проект уходит в GitHub и в «Скачать код». Вместо файла в проекте есть скрипт deploy/export-data.py. Вы запускаете его сами, а файл с данными появляется только на вашем компьютере или сервере. Переносятся пользователи, чаты, участники, темы, сообщения и реакции. Пароли переносятся в виде хешей, поэтому люди входят с прежними паролями.

Вам понадобится адрес базы на poehali.dev Скрипту нужна строка подключения к текущей базе проекта (секрет DATABASE_URL). Я не вижу значения секретов и не могу его вам передать. Посмотрите его в настройках секретов проекта на poehali.dev. Если там значение недоступно для просмотра, запросите внешний доступ к базе в поддержке: poehali.dev/help. Без этого адреса выгрузку сделать нельзя.

Шаг 1. Сделайте выгрузку на своём компьютере

Нужен Python 3 (python.org). В папке проекта выполните команды. Строку подключения вставьте вместо АДРЕС_БАЗЫ_POEHALI, внутри кавычек:

pip install psycopg2-binary
export SOURCE_DATABASE_URL="АДРЕС_БАЗЫ_POEHALI"
python3 deploy/export-data.py trindelka-data.sql

В конце скрипт напишет, сколько строк выгружено по каждой таблице. На момент подготовки в базе было: пользователей 11, чатов 16, участников чатов 34, тем 3, сообщений 102, реакций 6. Если цифры у вас сильно меньше, не продолжайте и проверьте адрес базы. Файл trindelka-data.sql создаётся с доступом только для вас и уже внесён в список игнорируемых файлов git, так что случайно в репозиторий он не попадёт.

Windows В PowerShell вместо export пишут: $env:SOURCE_DATABASE_URL="АДРЕС_БАЗЫ_POEHALI", а команду python3 заменяют на python. В Git Bash работает вариант выше.

Шаг 2. Передайте файл на сервер безопасно

Лучший способ: напрямую с вашего компьютера на сервер по SSH. Файл при этом идёт в зашифрованном виде и нигде по пути не хранится.

scp trindelka-data.sql root@IP_ВАШЕГО_СЕРВЕРА:/root/trindelka-data.sql

Если вы работаете с хостингом ISPmanager, вместо root укажите своего пользователя, а загрузить файл можно программой WinSCP или FileZilla по протоколу SFTP (не обычный FTP, он не шифрует).

Хуже по надёжности, но допустимо: загрузить через «Менеджер файлов» панели. Тогда загружайте вне папки сайта (в корень аккаунта, не в www), иначе файл можно будет скачать по ссылке.

Так делать нельзя
  • Отправлять файл по почте, в Telegram, WhatsApp или в чат с ИИ.
  • Класть файл в папку сайта, в public проекта или в репозиторий GitHub.
  • Загружать на файлообменники и общие облачные диски со ссылкой «для всех».

Шаг 3. Загрузите данные в новую базу

Сначала должны быть созданы таблицы (раздел 5, шаг 6) и база должна быть пустой: до этого момента никто не регистрировался. Затем:

export DATABASE_URL="postgresql://trindelka:ПАРОЛЬ@127.0.0.1:5432/trindelka"
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -1 -f /root/trindelka-data.sql

Ключ -1 загружает всё одной транзакцией: если что-то пойдёт не так, ничего не загрузится наполовину, и можно спокойно повторить после исправления. Проверьте итог:

psql "$DATABASE_URL" -c "SELECT (SELECT count(*) FROM t_p64541051_serge_chat_app.users) AS users, (SELECT count(*) FROM t_p64541051_serge_chat_app.chats) AS chats, (SELECT count(*) FROM t_p64541051_serge_chat_app.messages) AS messages;"

Цифры должны совпасть с тем, что показал скрипт на шаге 1.

Шаг 4. Уберите следы

shred -u /root/trindelka-data.sql

Удалите файл и на своём компьютере (trindelka-data.sql) после того, как убедитесь, что всё перенесено и сделана резервная копия новой базы (раздел 10). Если на сервере нет команды shred, используйте rm.

Не давайте пользователям писать, пока идёт перенос Всё, что люди напишут на poehali.dev после выгрузки, в новую базу не попадёт. Договоритесь о времени, когда мессенджер не используется, сделайте выгрузку, загрузите её и только потом переключайте людей на новый адрес.

8.2. Перенос файлов (аватары, фото, голосовые, документы)

В базе у файлов сохранены ссылки на хранилище платформы. Скрипт deploy/migrate-files.py скачивает все такие файлы в вашу папку files и заменяет ссылки в базе на ваши. Запускать после загрузки данных (пункт 8.1) и пока проект на poehali.dev ещё не удалён, иначе скачивать будет нечего.

cd /var/www/trindelka/app
set -a; . /etc/trindelka.env; set +a
/var/www/trindelka/venv/bin/python deploy/migrate-files.py
chown -R www-data:www-data /var/www/trindelka/files

В конце скрипт напишет, сколько файлов перенесено и сколько не удалось. Если часть не скачалась, запустите ещё раз: уже перенесённые повторно обрабатываться не будут.

На хостинге ISPmanager (сценарий А) Команды те же, только вместо /etc/trindelka.env укажите ~/trindelka-app/deploy/.env, а вместо /var/www/trindelka/venv/bin/python — ~/trindelka-app/venv/bin/python. Если на хостинге нет SSH, этот шаг нужно делать с любого компьютера с Python, указав адрес базы, к которой разрешён внешний доступ.

Пройдите по списку на новом адресе. Лучше с телефона и с компьютера.

  1. https://ваш-домен/api/health показывает status: ok.

10. Обновление сайта и резервные копии

Как обновить после новых правок (VPS)

Скрипт замены адресов меняет файлы проекта, поэтому перед обновлением его следы нужно откатить:

cd /var/www/trindelka/app
git checkout -- src index.html
git pull
sh deploy/replace-api-urls.sh /api
npm ci
npm run build
systemctl restart trindelka

Если менялись файлы таблиц, примените только новые файлы из db_migrations (с номером больше последнего применённого) командой psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f db_migrations/ИМЯ_ФАЙЛА.sql.

Резервная копия базы каждую ночь (VPS)

mkdir -p /var/backups/trindelka
crontab -l 2>/dev/null | { cat; echo '30 3 * * * sudo -u postgres pg_dump trindelka | gzip > /var/backups/trindelka/db-$(date +\%F).sql.gz && find /var/backups/trindelka -name "db-*.sql.gz" -mtime +14 -delete'; } | crontab -

Копии хранятся 14 дней. Также периодически копируйте на другой компьютер или в облако папки /var/backups/trindelka и /var/www/trindelka/files: копия на том же сервере не спасёт при его потере.

На хостинге ISPmanager резервные копии базы и файлов включаются в разделе «Резервные копии» панели или у хостера.

Приложение для Android (APK)

Проект подготовлен к сборке Android-приложения «Трынделка» (пакет ru.trindelka.messenger). Приложение показывает тот же мессенджер внутри оболочки Android и работает через интернет с вашим сервером. Готовый APK-файл собрать в среде poehali.dev нельзя: там нет Android SDK. Файл собирается у вас на компьютере за 10–20 минут.

Куда будет обращаться приложение По умолчанию в код зашиты адреса функций poehali.dev. Если вы уже перенесли проект на свой сервер, перед сборкой замените адреса на свой домен (шаг 2). Приложению нужен именно полный адрес с https://, а не короткий /api.

  1. Установите программы

    Node.js 20+ (nodejs.org), Git и Android Studio (developer.android.com/studio). При первом запуске Android Studio сама скачает Android SDK и нужную версию Java.

  2. Подготовьте проект

    Скачайте код проекта (раздел 4) и в папке проекта выполните. Первую строку выполняйте только если у вас свой сервер, подставив свой домен:

    sh deploy/replace-api-urls.sh https://ВАШ_ДОМЕН/api
npm ci
npm run android:sync

    Последняя команда собирает сайт и копирует его в папку android.

  3. Соберите APK

    Вариант А, через Android Studio: откройте папку android (File → Open), дождитесь окончания синхронизации и выберите Build → Build Bundle(s) / APK(s) → Build APK(s). Файл появится в android/app/build/outputs/apk/debug/app-debug.apk.

    Вариант Б, командой (нужны установленные Android Studio и Java 17):

    npm run android:apk

  4. Установите на телефон

    Передайте app-debug.apk на телефон кабелем или через облако, откройте его и разрешите установку из неизвестных источников. Это отладочная сборка: она работает как обычное приложение, но не подходит для Google Play и RuStore.

  5. Для публикации в магазинах

    В Android Studio: Build → Generate Signed Bundle / APK. Создайте ключ подписи и сохраните файл ключа и пароль в надёжном месте: без них нельзя будет выпускать обновления. RuStore принимает APK, Google Play требует формат AAB (в том же меню).

Что не проверено Сборку APK я здесь запустить не мог, поэтому приложение на реальном телефоне не проверялось. Проект Android создан штатными средствами Capacitor, иконка и разрешения (интернет, микрофон, камера) настроены. Вероятные места доработки: запись видеокружков и голосовых в оболочке Android, и ссылка из письма «Забыли пароль», которая откроет сайт в браузере, а не в приложении. Для писем задайте адрес сайта в настройке PUBLIC_SITE_URL.

Уведомления, звонки, GIF и вставка файлов на своём сервере

Эти функции работают из коробки на poehali.dev. При переносе на свой сервер нужно учесть несколько условий.

Обязательно: только по HTTPS

Уведомления при закрытом приложении и звонки (микрофон и камера) браузер разрешает только на сайте с https://. Без сертификата (часть 1, шаг 12) они не заработают. Исключение — адрес localhost для проверки.

Уведомления при закрытом приложении

  • Ключи для уведомлений сервер создаёт сам при первом запуске и хранит в базе (таблица app_settings). Ничего вручную настраивать не нужно. Если вы переносите базу выгрузкой, ключи переедут вместе с ней, и устройства, уже подписанные на уведомления, продолжат получать их.
  • В /etc/trindelka.env можно указать PUSH_CONTACT — вашу почту для связи (необязательно, по умолчанию берётся SMTP_FROM_EMAIL).
  • Файл sw.js должен лежать в корне сайта и отдаваться без кеширования. В готовом deploy/nginx.conf это уже сделано. На хостинге ISPmanager он попадёт в корень вместе с содержимым dist (файл берётся из папки public).
  • Включать уведомления каждый пользователь должен сам: Профиль → Уведомления → «Уведомления на устройстве». Для каждого чата там же есть свой переключатель.
  • iPhone: уведомления работают только если добавить сайт на экран «Домой» (Поделиться → На экран «Домой») и открыть его оттуда. Нужна iOS 16.4 или новее.
  • Приложение APK: уведомления через браузерный механизм в нём не работают. Для APK нужна отдельная настройка Firebase (Google), она не входит в этот перенос.
  • Серверу нужен выход в интернет на порт 443: уведомления уходят через серверы Google, Mozilla и Apple. Из России доступность этих серверов может быть нестабильной, это зависит от вашего провайдера.

Звонки

  • Звонки идут напрямую между телефонами или компьютерами, сервер только соединяет собеседников. Работают в личных чатах между двумя людьми (в группах недоступны).
  • В большинстве случаев хватает бесплатных серверов Google для соединения. Но если у кого-то строгий роутер, корпоративная сеть или мобильный интернет с закрытыми соединениями, звонок может не соединиться. Для таких случаев нужен собственный TURN-сервер, например coturn на VPS. Когда он у вас будет, впишите в /etc/trindelka.env адреса и данные доступа:
TURN_URL=turn:ваш-домен:3478,turns:ваш-домен:5349
TURN_USER=логин
TURN_PASSWORD=пароль

Firebase: уведомления в Android-приложении

Чтобы сообщения и звонки приходили в приложение, пока оно закрыто, нужен бесплатный проект Firebase (сервис Google). Нужно один раз сделать три вещи: создать проект, положить в приложение один файл и передать серверу один ключ. Платить ничего не нужно.

Нужен аккаунт Google Любой обычный адрес gmail.com. Используйте тот, к которому у вас всегда будет доступ: на него записывается проект.

  1. Создайте проект Firebase

    Откройте console.firebase.google.com → «Создать проект» (Add project) → введите название, например Trindelka → отключите Google Analytics (он не нужен) → «Создать проект».

  2. Добавьте Android-приложение

    На главной странице проекта нажмите значок Android. Заполните:

    • Имя пакета Android: ru.trindelka.messenger (вводите точно так, без пробелов и с маленькими буквами)
    • Псевдоним: «Трынделка» (необязательно)
    • SHA-1 оставьте пустым

    Нажмите «Зарегистрировать приложение».

  3. Скачайте файл google-services.json

    На следующем шаге нажмите «Скачать google-services.json» и положите этот файл в папку проекта android/app/ (рядом с файлом build.gradle). Остальные шаги в Firebase («Добавьте SDK», «Запустите приложение») пропускайте: всё уже настроено в проекте, просто нажимайте «Далее» и «Перейти к консоли».

    Этот файл не секретный, но не выкладывайте его в общий репозиторий без необходимости: в проекте он уже добавлен в список игнорируемых файлов.

  4. Получите ключ для сервера

    В Firebase: значок шестерёнки рядом с «Обзор проекта» → «Настройки проекта» → вкладка «Сервисные аккаунты» → кнопка «Создать новый закрытый ключ» → «Создать ключ». Скачается файл с расширением .json.

    Откройте его в обычном Блокноте, скопируйте весь текст (от первой фигурной скобки до последней) и вставьте в секрет проекта FIREBASE_SERVICE_ACCOUNT (окно с полем ввода уже показано в чате poehali.dev).

    Этот файл даёт полный доступ к отправке уведомлений от вашего имени. Никому его не отправляйте, не выкладывайте в GitHub и не присылайте в мессенджеры. Если файл утёк, в тех же «Сервисных аккаунтах» удалите ключ и создайте новый.

    На своём сервере (не poehali.dev) вставьте тот же текст одной строкой в /etc/trindelka.env: FIREBASE_SERVICE_ACCOUNT={"type":"service_account",...}. Строка должна быть без переносов. Проще всего открыть файл в Блокноте, убрать переносы строк и вставить.

  5. Включите API отправки уведомлений

    Обычно он уже включён. Если уведомления не приходят, откройте страницу Firebase Cloud Messaging API, выберите свой проект сверху и нажмите «Включить» (Enable).

  6. Пересоберите приложение

    После добавления файла выполните сборку заново по разделу «Приложение для Android» (npm run android:sync, затем сборка APK). Без пересборки приложение продолжит работать, но уведомления не придут.

  7. Включите уведомления в приложении

    Установите новый APK, войдите, откройте «Профиль» → «Уведомления» и включите «Уведомления на устройстве». Телефон спросит разрешение (Android 13 и новее): нажмите «Разрешить». Закройте приложение и отправьте себе сообщение с другого аккаунта.

Как это работает Приложение при входе получает от Google уникальный адрес телефона и отправляет его на сервер. Когда приходит сообщение или звонок, сервер просит Google доставить уведомление на этот адрес. Для звонков создан отдельный канал с высоким приоритетом: уведомление выскакивает сверху и вибрирует.
Ограничения
  • На телефонах без сервисов Google (например, часть Huawei) уведомления через Firebase не работают.
  • Некоторые производители (Xiaomi, Huawei, Oppo, Samsung) агрессивно закрывают фоновые приложения. Если уведомления приходят с задержкой, в настройках телефона разрешите приложению «Трынделка» работу в фоне и автозапуск.
  • Входящий звонок при закрытом приложении приходит как обычное уведомление с кнопкой нажатия. Полноэкранный «звонок как в телефоне» на заблокированном экране не делался: он требует отдельной доработки.
  • Я не мог проверить это на настоящем телефоне и аккаунте Firebase. Отправка на сервере проверена на тестовом сервере Google с проверкой подписи, а само приложение нужно пройти руками.

Группы, поиск GIF, смайлы, галочки, сессии

Групповые звонки

  • В любой группе в шапке есть кнопки группового звонка и видеозвонка. Звонок можно начать, пока никто другой его не начал; остальные участники видят в чате полосу «Идёт звонок · Присоединиться» и получают уведомление.
  • Одновременно в звонке могут быть до 6 человек: при больше качество резко падает, потому что каждый телефон отправляет видео каждому. Седьмой участник увидит сообщение, что мест нет.
  • Звонок идёт напрямую между устройствами. Если у людей строгая сеть или мобильный интернет с закрытыми соединениями, часть людей может не слышать друг друга. Для этого нужен собственный TURN-сервер (раздел про звонки выше), в группах он важнее, чем в звонках один на один.
  • Когда выходит последний участник, в чате остаётся запись: «Групповой звонок · длительность · участников: N».
  • На слабых телефонах групповой видеозвонок на 5–6 человек будет греть устройство и тормозить. Для больших групп лучше голосовой звонок.

Живой поиск GIF

В окне выбора на вкладке GIF поиск идёт по большой библиотеке сервиса KLIPY. Для работы нужен бесплатный ключ:

  1. Откройте partner.klipy.com и зарегистрируйтесь.
  2. В разделе «API Keys» создайте платформу (название любое, например «Трынделка») и скопируйте ключ.
  3. Вставьте его в секрет KLIPY_API_KEY. На своём сервере: строка KLIPY_API_KEY=ваш_ключ в /etc/trindelka.env.
Тестовый режим Пока ключ в тестовом режиме, работает до 100 запросов в час на весь мессенджер, этого мало для живых людей. В том же кабинете запросите «Production access»: тогда лимит снимается. Правила сервиса также требуют показывать надпись KLIPY рядом с GIF. Она уже есть под списком результатов. Если ключ не указан или не принят, в окне остаются 12 встроенных GIF, ничего не ломается.

Галочки доставки и прочтения

  • Одна серая галочка: сообщение отправлено. Две серые: собеседник был в сети после отправки. Две фиолетовые: прочитано.
  • В группах рядом с галочками число «прочитали/всего», например 2/5. Если подержать курсор на галочках (или нажать), появится подсказка «Прочитали 2 из 5».
  • Участники, у которых в «Приватность» отключены отметки о прочтении, в подсчёт не входят и сами тоже не видят чужих отметок. Это общее правило мессенджера.
  • В группе показывается только число прочитавших. Списка «кто именно прочитал» нет.

Сохранение входа на 6 месяцев

  • После входа или регистрации человек остаётся авторизованным 6 месяцев. Даже если закрыть браузер или приложение, вход не потребуется.
  • По истечении срока все запросы к серверу отвечают, что сеанс завершён. Приложение само закрывает вход и показывает экран входа с пояснением «прошло больше 6 месяцев».
  • Срок считается с последнего входа по паролю, а не с последнего захода в приложение. Тот, кто заходит каждый день, всё равно должен будет ввести пароль раз в полгода.
  • Тех, кто уже был в мессенджере до этого обновления, срок посчитан от дня обновления: они должны будут войти заново через 6 месяцев после него.
  • После смены пароля по ссылке из письма сеанс продлевается на новые 6 месяцев, а старые сеансы на других устройствах закрываются.
Один аккаунт, один сеанс Как и раньше, вход с нового устройства закрывает прошлый сеанс на старом. Это поведение я не менял.

Ночное резервное копирование и восстановление

На своём сервере (часть 1 инструкции) каждую ночь в 03:30 делается копия: вся база (пользователи, чаты, сообщения, опросы) и все загруженные файлы (аватары, фото, голосовые). Старше 14 дней копии удаляются сами. На poehali.dev резервные копии делает платформа, этот раздел только для вашего сервера.

Включить за 4 минуты (VPS)

apt install -y postgresql-client openssl rsync
chmod +x /var/www/trindelka/app/deploy/backup.sh /var/www/trindelka/app/deploy/restore.sh
cp /var/www/trindelka/app/deploy/trindelka-backup.service /etc/systemd/system/
cp /var/www/trindelka/app/deploy/trindelka-backup.timer /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now trindelka-backup.timer

Проверьте, что таймер встал, и сразу сделайте первую копию вручную:

systemctl list-timers trindelka-backup.timer
systemctl start trindelka-backup.service
journalctl -u trindelka-backup.service -n 20 --no-pager
ls -lh /var/backups/trindelka

В журнале должна быть строка «Готово» с размером файла. Копии лежат в /var/backups/trindelka/trindelka-ДАТА.tar, доступ к ним только у администратора сервера.

Настройки (в /etc/trindelka.env)

СтрокаЧто делает
KEEP_DAYS=14Сколько дней хранить копии на сервере.
BACKUP_PASSPHRASE=ваш_парольШифрует копию (AES-256). Файл получит окончание .tar.enc. Запишите пароль в надёжное место: без него копию не открыть. Пока пароль не задан, копия не зашифрована и файл настроек (с вашими паролями и ключами) в неё не кладётся.
BACKUP_REMOTE=user@другой-сервер:/backups/После создания копия отправляется на другой сервер через rsync (нужен доступ по SSH-ключу). Так вы не потеряете данные, если сломается сам сервер.
BACKUP_DIR=/путьДругая папка для копий.
Копия на том же сервере не спасёт, если сервер пропадёт Обязательно настройте BACKUP_REMOTE или раз в неделю скачивайте свежий файл на свой компьютер программой WinSCP или FileZilla (по SFTP): папка /var/backups/trindelka.

Как восстановить из копии

Подходит и для переезда на новый сервер: поставьте проект по части 1 до шага 6 (пустая база, без загрузки данных), затем:

systemctl stop trindelka
cd /var/www/trindelka/app/deploy
./restore.sh /var/backups/trindelka/trindelka-ДАТА.tar
systemctl start trindelka
  • Скрипт проверяет целостность копии: если файл повреждён, восстановление не начнётся.
  • Перед заменой базы он спрашивает подтверждение: нужно ввести слово ДА. Текущая база будет заменена целиком.
  • Для зашифрованной копии (.tar.enc) задайте пароль: BACKUP_PASSPHRASE='пароль' ./restore.sh файл.tar.enc.
  • Файлы (аватары, фото, голосовые) возвращаются в папку, указанную в LOCAL_STORAGE_DIR. Права на папку: chown -R www-data:www-data /var/www/trindelka/files.
  • Копию нужно проверять: раз в месяц восстановите её на тестовом сервере и убедитесь, что люди и сообщения на месте. Непроверенная копия может оказаться пустой.

Хостинг с ISPmanager

  • Если у вас нет доступа к системному планировщику (виртуальный хостинг), используйте встроенные резервные копии панели: «Резервные копии» включает и сайт, и базу данных. Включите ежедневное копирование базы PostgreSQL и папки files.
  • Если есть SSH и «Планировщик» (cron) в панели, добавьте задание на 03:30: ENV_FILE=~/trindelka-app/deploy/.env BACKUP_DIR=~/backups sh ~/trindelka-app/deploy/backup.sh (нужен установленный pg_dump).
  • На VPS с ISPmanager работает вариант для VPS выше.

Версии PostgreSQL Копию можно восстанавливать на сервере с версией PostgreSQL не старше той, где она сделана, либо такой же. Если на новом сервере версия старее, скрипт сам убирает из копии несовместимые строки настроек, но самый надёжный путь — ставить на новом сервере ту же или более новую версию.

Стикеры, опросы, настроение и краткий профиль

Стикеры

  • В окне смайлов появилась вкладка «Стикеры»: 4 набора (зверята, еда, эмоции, праздник), всего 48 крупных картинок. Нажатие отправляет стикер сразу, он показывается в чате крупно, без пузыря.
  • Звёздочка в углу стикера сохраняет его в «Избранное» (вкладка со звездой слева). Избранное личное, хранится на сервере, до 60 штук.
  • Картинки лежат в папке public/stickers и входят в сборку сайта, внешние сервисы не нужны. Это эмодзи Google Noto (лицензия Apache 2.0), поэтому их можно использовать свободно, но своих авторских наборов среди них нет.
  • Добавить свой набор: положите PNG (до 256 пикселей) в новую папку и допишите набор в src/components/messenger/stickers/stickerCatalog.ts, а на сервере в проверку адресов в backend/chats/index.py (строка STICKER_RE). Если нужно, чтобы это сделал я, просто напишите.

Опросы в группах

  • В группе: скрепка → «Опрос». Вопрос до 300 символов, от 2 до 10 вариантов, галочка «Можно выбрать несколько».
  • Пока человек не проголосовал, он видит варианты. После голосования появляются проценты и полоски. Проценты считаются от числа проголосовавших людей, поэтому в опросе с несколькими ответами сумма может быть больше 100%.
  • Свой голос можно изменить («Изменить») или забрать. Опрос завершает его автор, администратор или владелец группы кнопкой «Завершить»: после этого голосовать нельзя, а результаты остаются.
  • Кнопка «Кто» показывает, кто как проголосовал. Опросы не анонимные: это видят все участники группы.
  • В личных чатах опросов нет, только в группах.

Настроение и «о себе»

  • «Профиль → Настроение и о себе»: эмодзи (12 готовых), короткая фраза до 80 символов и описание «о себе» до 200 символов.
  • Эмодзи и фраза видны в шапке личного чата рядом с именем и в списке участников группы. Описание «о себе» открывается в кратком профиле.
  • Видят их только те, у кого с вами есть общий чат.

Краткий профиль человека и группы

  • Человек: нажмите на имя и фото в шапке личного чата, на аватар автора сообщения в группе или на участника в списке участников. Откроется карточка: фото, имя, логин, статус «в сети», настроение, «о себе», общие группы и кнопка «Написать».
  • Группа: нажмите на название в шапке группы. Откроется карточка с фото, описанием, числом участников и вашей ролью, оттуда можно перейти к участникам и настройкам.
  • Если человек скрыл статус «в сети» в приватности, в карточке статус тоже скрыт.
Для своего сервера Новые таблицы (опросы, избранные стикеры, настроение) создаёт файл базы V0019. Команда применения всех файлов из части 1, шаг 6, подхватывает его сама. Для старых данных ничего переносить не нужно.

11. Если что-то не работает

Что видитеПричина и что делать
Белая страницаЗагружена не собранная папка dist, или файлы лежат во вложенной папке. В корне сайта должен быть index.html и папка assets.
Ошибка 502 Bad GatewayСерверная часть не запущена. VPS: systemctl status trindelka и journalctl -u trindelka -n 50 --no-pager.
«Не удалось связаться с сервером» при входеЗапросы не доходят до /api. Откройте в браузере /api/health. Если там не JSON, значит не настроен nginx (шаг 11) или Python на хостинге. Также проверьте, что запускали replace-api-urls.sh до сборки.
Вход выдаёт ошибку 500Неверный DATABASE_URL или не созданы таблицы. Смотрите журнал службы: там будет текст ошибки базы.
Ошибка про отсутствующую таблицу или схемуНе создана схема t_p64541051_serge_chat_app или не применены файлы из db_migrations.
Страница /reset-password даёт 404Не настроено открытие внутренних адресов (часть 2, шаг 3, или блок try_files в nginx).
Письма не приходятПроверьте SMTP_* в настройках. Для Яндекса и Gmail нужен пароль приложения. Порт 465 использует SSL, остальные порты — STARTTLS. Загляните в папку «Спам». Ошибки отправки пишутся в журнал службы.
Аватар или картинка не отображаетсяПроверьте PUBLIC_FILES_URL (схема https://, ваш домен, /files на конце без слеша), права на папку files и что LOCAL_STORAGE_DIR указывает на неё.
Загрузка файла выдаёт ошибкуПапка files недоступна для записи, либо файл больше лимита. Лимиты в проекте: до 8 МБ для фото и документов, до 6 МБ для голосовых и кружков. В nginx также стоит client_max_body_size 25m.
Не приходят уведомления при закрытом приложенииПроверьте, что сайт открыт по https://, что в профиле включён переключатель «Уведомления на устройстве» и что у чата переключатель не выключен. На iPhone сайт должен быть добавлен на экран «Домой». Серверу нужен выход на порт 443.
Звонок не соединяется или нет звукаНужен https:// и разрешение на микрофон (камеру) в браузере. Если у собеседников строгая сеть, понадобится свой TURN-сервер (см. раздел про звонки).
Ночная копия не создаётсяПосмотрите журнал: journalctl -u trindelka-backup.service -n 30 --no-pager. Частые причины: не установлен postgresql-client (нет команды pg_dump), задан BACKUP_PASSPHRASE, но нет openssl, не хватает места на диске (df -h).
Звонок в Android приходит, но не открывается на весь экранAndroid 14 и новее: в «Профиль → Уведомления» нажмите «Разрешить» в строке «Звонки на весь экран». На телефонах Xiaomi, Huawei, Oppo, Samsung в настройках приложения «Трынделка» включите «Показ поверх экрана блокировки», «Всплывающие окна» и автозапуск.
В Android-приложении не приходят уведомленияПроверьте по порядку: в проект добавлен файл google-services.json и приложение собрано заново после этого; в секрете FIREBASE_SERVICE_ACCOUNT лежит весь текст файла ключа; включён «Firebase Cloud Messaging API»; на телефоне разрешены уведомления и фоновая работа; в профиле включён переключатель «Уведомления на устройстве». После смены пароля или повторного входа его нужно включить снова.
Поиск GIF пишет «Ключ Klipy не принят»Проверьте секрет KLIPY_API_KEY: ключ должен быть скопирован целиком, без пробелов. Если вы в тестовом режиме и превысили лимит 100 запросов в час, подождите или запросите Production access.
Не работает расшифровка голосовыхНе указан OPENAI_API_KEY, либо с сервера нет доступа к OpenAI. Остальные функции от этого не зависят.
Ошибка 402 Payment RequiredЭто ответ платформы poehali.dev: исчерпан лимит вызовов функций. Появляется только в сценарии Б (или пока сайт ещё ходит на poehali.dev). При работе на своём сервере не возникает.
