1. Из чего состоит проект

Мессенджер состоит из пяти частей. При переносе на свой сервер каждая ставится отдельно:

ЧастьЧто этоГде будет на вашем сервере
СайтПриложение на TanStack Start (React). Страницы сначала собираются на сервере, потом оживают в браузере. Собирается в папку dist: dist/client (картинки, скрипты, стили) и dist/server (серверная часть сайта)Служба trindelka-web на порту 3000, перед ней nginx
Серверные функции5 функций на Python 3: auth (вход, профиль), chats (чаты, группы, настройки, поиск, опросы, стикеры), send-message (отправка, пересылка, файлы, запланированные), transcribe (голос в текст), push (уведомления, звонки, GIF)Служба trindelka (обёртка из deploy/app.py) на порту 8000, адреса /api/...
База данныхPostgreSQL, 23 таблицы. Создаются файлами из db_migrationsPostgreSQL на сервере
ФайлыАватары, фото, документы, голосовые, кружки, свои стикерыПапка /var/www/trindelka/files
Минутный таймерОтправляет запланированные сообщения, у которых наступило времяТаймер trindelka-dispatch.timer
Важное изменениеРаньше сайт был набором готовых файлов, и его можно было выложить на любой хостинг. Теперь у сайта есть серверная часть на Node.js, поэтому нужен VPS с правами root. Обычный виртуальный хостинг (ISPmanager и подобные) для нового сайта не подходит, и в этой инструкции его нет.
Что не провереноКоманды для запуска нового сайта я составил по документации и исходникам движка, но на реальном сервере не проверял: у меня нет доступа к вашему VPS. Поэтому сначала сделайте пробный запуск и пройдите чек-лист из раздела 6, и только потом переключайте людей.

2. Что подготовить заранее

  • VPS с Ubuntu 22.04 или 24.04 и правами root. Подойдёт 1–2 ядра и 2 ГБ памяти (сборка сайта занимает 1–3 минуты и любит память).
  • Домен, например chat.example.ru. В DNS у регистратора добавьте запись A на IP сервера. Применение может занять до нескольких часов.
  • SSH-доступ: IP, логин и пароль или ключ. На Windows подойдёт PuTTY или встроенный ssh в PowerShell.
  • Почта для писем восстановления пароля: адрес SMTP-сервера, порт (465 или 587), логин и пароль. Для Яндекса и Gmail нужен «пароль приложения», а не основной пароль.
  • Значения ваших секретов с poehali.dev (список в разделе 5). Я не вижу значений секретов, их нужно открыть в настройках секретов проекта самим.
  • CSV-файлы таблиц с poehali.dev, если нужно перенести людей и переписку (как их скачать, см. раздел 4). Адрес базы и внешний доступ к ней не нужны.
Придумывайте длинные пароли из латинских букв и цифр. Если в пароле есть символы @ : / # ?, в адресе базы их придётся кодировать (например, @ превращается в %40).

3. Установка на VPS Ubuntu

Все команды выполняются на сервере под пользователем root. Где написано example.ru, подставьте свой домен, а вместо ПАРОЛЬ вставьте придуманный пароль базы.

  1. Подключитесь и обновите систему 
    ssh root@IP_ВАШЕГО_СЕРВЕРА
apt update && apt upgrade -y
  2. Установите программы 
    apt install -y nginx postgresql postgresql-contrib python3 python3-venv python3-pip git curl ufw certbot python3-certbot-nginx
curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
apt install -y nodejs
node -v

    Последняя команда должна показать v22 или выше. Движку сайта нужен Node.js не ниже 22.12.

  3. Включите защиту 
    ufw allow OpenSSH
ufw allow 'Nginx Full'
ufw --force enable

    Не пропускайте ufw allow OpenSSH до включения защиты, иначе потеряете доступ к серверу.

  4. Скачайте код 
    mkdir -p /var/www/trindelka/files
cd /var/www/trindelka
git clone https://github.com/ВАШ_АККАУНТ/ВАШ_РЕПОЗИТОРИЙ.git app

    Код берётся в меню проекта: Скачать → Подключить GitHub (удобнее, потом обновляется командой git pull) или Скачать → Скачать код (архив; распакуйте так, чтобы получилась папка /var/www/trindelka/app с папками src, backend, deploy).

  5. Создайте базу данных 
    sudo -u postgres psql -c "CREATE USER trindelka WITH PASSWORD 'ПАРОЛЬ';"
sudo -u postgres psql -c "CREATE DATABASE trindelka OWNER trindelka;"
cd /var/www/trindelka/app
SCHEMA=$(sed -n 's/^SCHEMA = "\(.*\)"$/\1/p' backend/chats/index.py)
echo "$SCHEMA"
sudo -u postgres psql -d trindelka -c "CREATE SCHEMA \"$SCHEMA\" AUTHORIZATION trindelka;"

    Имя схемы прописано в коде серверных функций и в файлах таблиц, поэтому его не придумывают: команда выше сама достаёт его из кода. Команда echo должна вывести непустое имя.

  6. Создайте таблицы 
    export DATABASE_URL="postgresql://trindelka:ПАРОЛЬ@127.0.0.1:5432/trindelka"
export PGOPTIONS="-c search_path=$SCHEMA"
for f in $(ls db_migrations/*.sql | grep -v -e V0003 -e V0005); do
  echo "== $f"
  psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -q -f "$f" || break
done
psql "$DATABASE_URL" -c "SELECT count(*) FROM information_schema.tables WHERE table_schema = '$SCHEMA'"

    Файлы применяются по порядку, всего 22 (до V0023). Два файла с демонстрационными данными (V0003 и V0005) пропускаются. Последняя команда должна показать 23 таблицы. Переменная PGOPTIONS нужна: в новых файлах (V0020, V0021, V0023) имя схемы не указано и берётся из неё. Если остановились на ошибке, исправьте причину и запустите цикл снова: файлы написаны так, что повторный запуск безопасен.

  7. Установите серверные функции 
    cd /var/www/trindelka
python3 -m venv venv
./venv/bin/pip install -r app/deploy/requirements.txt
  8. Создайте файл настроек 
    cp /var/www/trindelka/app/deploy/env.example /etc/trindelka.env
chmod 600 /etc/trindelka.env
nano /etc/trindelka.env

    Заполните значения (что откуда брать, см. раздел 5). Минимум для старта: DATABASE_URL, LOCAL_STORAGE_DIR, PUBLIC_FILES_URL, PUBLIC_SITE_URL, SEND_MESSAGE_URL и данные почты. Без кавычек и пробелов вокруг «=». Сохранить в nano: Ctrl+O, Enter, выйти: Ctrl+X.

  9. Соберите сайт 
    cd /var/www/trindelka/app
sh deploy/prepare-selfhost.sh
npm install
VITE_API_BASE=/api npm run build
ls dist/client dist/server

    Первая команда отключает служебные скрипты платформы poehali.dev в вашей копии. VITE_API_BASE=/api говорит сайту обращаться к функциям на вашем же домене. В dist/server должен появиться файл server.js, в dist/client папка assets. Если сборка падает с нехваткой памяти, добавьте на сервер файл подкачки (swap) или соберите на другом компьютере и скопируйте папку dist.

    В файле src/routes/__root.tsx подключён счётчик Яндекс.Метрики платформы. Если он вам не нужен, удалите блок METRIKA_SCRIPT до сборки; если нужен ваш, замените номер счётчика.
  10. Запустите службы 
    chown -R www-data:www-data /var/www/trindelka/files
cd /var/www/trindelka/app/deploy
cp trindelka.service trindelka-web.service trindelka-dispatch.service trindelka-dispatch.timer trindelka-backup.service trindelka-backup.timer /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now trindelka trindelka-web trindelka-dispatch.timer trindelka-backup.timer
curl -s http://127.0.0.1:8000/api/health
curl -sI http://127.0.0.1:3000/ | head -1

    Первая проверка должна вернуть {"functions":[...],"status":"ok"}, вторая — HTTP/1.1 200 OK. Если нет, смотрите журнал: journalctl -u trindelka -n 50 --no-pager или journalctl -u trindelka-web -n 50 --no-pager.

  11. Подключите nginx 
    cp /var/www/trindelka/app/deploy/nginx.conf /etc/nginx/sites-available/trindelka
sed -i 's/example.ru/ВАШ_ДОМЕН/g' /etc/nginx/sites-available/trindelka
ln -s /etc/nginx/sites-available/trindelka /etc/nginx/sites-enabled/trindelka
rm -f /etc/nginx/sites-enabled/default
nginx -t && systemctl reload nginx

    nginx сам отдаёт файлы сайта из dist/client, загруженные файлы из /files/, /api/ отправляет в функции, а всё остальное — на сайт (служба trindelka-web).

  12. Включите HTTPS 
    certbot --nginx -d ВАШ_ДОМЕН -d www.ВАШ_ДОМЕН --redirect -m ваша_почта@example.ru --agree-tos -n

    Если у домена нет www, уберите часть -d www.ВАШ_ДОМЕН. Сертификат продлевается сам. Убедитесь, что в /etc/trindelka.env адреса PUBLIC_FILES_URL и PUBLIC_SITE_URL начинаются с https://, и перезапустите: systemctl restart trindelka.

    Уведомления при закрытом приложении, звонки и запись голоса работают только по HTTPS.

4. Перенос базы, пользователей и файлов

Шаги из раздела 3 создают чистый мессенджер без людей. Чтобы сохранить зарегистрированных пользователей, переписку, группы, опросы, стикеры и запланированные сообщения, нужно перенести данные. Внешний доступ к базе poehali.dev не нужен: данные переносятся через CSV-файлы, которые можно скачать по каждой таблице на самой платформе. Эти файлы содержат почты, хеши паролей и сообщения живых людей, поэтому их нет в проекте и не должно быть. Вы скачиваете их сами и храните только у себя.

Пока идёт перенос, мессенджером никто не должен пользоваться. Всё, что люди напишут на poehali.dev после скачивания файлов, в новую базу не попадёт. Договоритесь о времени, скачайте файлы, загрузите их и только потом переключайте людей на новый адрес.
  1. Скачайте таблицы в CSV на poehali.dev

    Откройте базу данных вашего проекта на poehali.dev и скачайте каждую таблицу из списков ниже. Сохраните все файлы в одну папку на своём компьютере, например trindelka-csv. Имя файла должно совпадать с именем таблицы: users.csv, messages.csv и так далее. Если платформа добавила к имени дату или название схемы, скрипт всё равно узнает таблицу по окончанию имени, но проще переименовать файл.

    Обязательные таблицы (без них загрузка не начнётся):

    ФайлЧто внутри
    users.csvлюди, почты и пароли
    chats.csvчаты и группы
    chat_members.csvкто в каких чатах, роли, фон чата
    messages.csvвсе сообщения

    Остальные таблицы. Если таблица пустая или её нет, файл можно не скачивать:

    ФайлЧто внутри
    chat_topics.csvтемы в группах
    message_reactions.csvреакции
    hidden_messages.csv«удалить у меня»
    polls.csvопросы
    poll_options.csvварианты опросов
    poll_votes.csvголоса
    poll_shares.csvпересланные опросы
    sticker_packs.csvнаборы стикеров
    custom_stickers.csvсвои стикеры
    favorite_stickers.csvизбранные стикеры
    scheduled_messages.csvзапланированные сообщения
    push_tokens.csvустройства Android для уведомлений

    Не нужно скачивать: calls, group_calls, group_call_members, group_call_signals (временные данные звонков), app_settings (ключи уведомлений сервер создаст сам) и push_subscriptions (подписки браузеров привязаны к старому адресу). Если такие файлы окажутся в папке, скрипт их пропустит.

    Запишите, сколько строк в каждой таблице (платформа обычно показывает это рядом с таблицей). Цифры понадобятся для сверки в шаге 3. Если платформа скачивает только часть строк или ограничивает размер, выгружайте таблицу частями и соберите их в один файл: заголовок с названиями колонок должен быть только в первой строке файла. Если в файлах нет колонки id или названий колонок, загрузка не получится: скачайте таблицы заново с полным набором колонок.

  2. Передайте папку на сервер 
    scp -r trindelka-csv root@IP_ВАШЕГО_СЕРВЕРА:/root/trindelka-csv

    Только так (по SSH) или через SFTP (WinSCP, FileZilla). Нельзя отправлять файлы по почте, в мессенджеры, в чат с ИИ, класть в папку сайта или репозиторий GitHub.

  3. Загрузите данные в новую базу 
    cd /var/www/trindelka/app
set -a; . /etc/trindelka.env; set +a
systemctl stop trindelka
/var/www/trindelka/venv/bin/python deploy/import-csv.py /root/trindelka-csv
export PGOPTIONS="-c search_path=$(sed -n 's/^SCHEMA = "\(.*\)"$/\1/p' backend/chats/index.py)"
psql "$DATABASE_URL" -c "SELECT (SELECT count(*) FROM users) AS users, (SELECT count(*) FROM chats) AS chats, (SELECT count(*) FROM messages) AS messages"

    Дополнительно ничего устанавливать не нужно: нужные библиотеки уже стоят после раздела 3. Скрипт сам определяет схему, порядок таблиц по связям, разделитель (запятая или точка с запятой) и кодировку файла (UTF-8 или Windows-1251). Затем загружает всё одной транзакцией: если в каком-то файле ошибка, он скажет, в каком файле и в какой строке, и ничего не загрузится наполовину. Исправьте файл и запустите команду ещё раз. В конце скрипт выводит, сколько строк загружено по каждой таблице. Сверьте эти цифры и итоговый запрос с тем, что вы записали в шаге 1: они должны совпасть. База перед загрузкой должна быть пустой, то есть до этого никто не регистрировался, иначе скрипт остановится.

    Ошибка «password authentication failed for user trindelka»Пароль в /etc/trindelka.env (строка DATABASE_URL) не совпадает с паролем пользователя в базе. Проверьте, что там нет CHANGE_ME. Проще всего задать пароль заново, подставив один и тот же в обе команды (только латинские буквы и цифры): 
    sudo -u postgres psql -c "ALTER USER trindelka WITH PASSWORD 'НОВЫЙ_ПАРОЛЬ';"
nano /etc/trindelka.env
psql "postgresql://trindelka:НОВЫЙ_ПАРОЛЬ@127.0.0.1:5432/trindelka" -c "SELECT 1"
    В nano исправьте пароль в DATABASE_URL. Если последняя команда вывела таблицу с единицей, пароль верный: запустите загрузку из шага 3 ещё раз. Эту же ошибку может дать пароль с символами @ : / # ?: замените его на простой.
  4. Перенесите файлы (аватары, фото, документы, стикеры) 
    set -a; . /etc/trindelka.env; set +a
/var/www/trindelka/venv/bin/python deploy/migrate-files.py
chown -R www-data:www-data /var/www/trindelka/files
systemctl start trindelka

    В базе у файлов остались ссылки на хранилище платформы. Скрипт скачивает все такие файлы в вашу папку и заменяет ссылки в базе: в аватарах, фото, своих стикерах, фонах чатов и запланированных сообщениях. Запускать нужно, пока проект на poehali.dev ещё не удалён. Если часть файлов не скачалась, запустите ещё раз: уже скачанные пропускаются.

  5. Уберите следы 
    find /root/trindelka-csv -type f -exec shred -u {} \;
rmdir /root/trindelka-csv

    Удалите папку с файлами и на своём компьютере после того, как убедились, что всё перенесено и сделана резервная копия новой базы.

Что заметят людиСайт теперь на другом адресе, поэтому браузер не помнит вход: людям придётся один раз войти заново с тем же паролем. Подписки на уведомления привязаны к старому адресу, их нужно включить заново: Профиль → Уведомления.

5. Перенос секретов

Секреты проекта на poehali.dev на ваш сервер сами не переезжают. Их значения я прочитать не могу, поэтому откройте настройки секретов проекта и по таблице перепишите нужные в файл /etc/trindelka.env (по одной строке вида ИМЯ=значение). После правки выполните systemctl restart trindelka.

Секрет на poehali.devИмя в /etc/trindelka.envПереносить значение как есть?
DATABASE_URLDATABASE_URLНет, свой: адрес вашей новой базы. Старый нужен только один раз для выгрузки
MAIN_DB_SCHEMAне нуженИмя схемы берётся из кода
AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEYне нужныФайлы лежат в папке на сервере (LOCAL_STORAGE_DIR). Ключи пригодятся только для скачивания файлов старым скриптом, а он ходит по публичным ссылкам
SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASSWORD, SMTP_FROM_EMAILто же имяДа, можно взять те же
PUBLIC_SITE_URLто же имяНет: впишите новый адрес сайта с https://
OPENAI_API_KEYто же имяДа. Нужен только для расшифровки голосовых. С российских серверов доступ к OpenAI может быть закрыт
KLIPY_API_KEYто же имяДа. Нужен для живого поиска GIF. Без него работают встроенные GIF
FIREBASE_SERVICE_ACCOUNTто же имяДа, весь JSON одной строкой без переносов. Нужен для уведомлений в Android-приложении

Новые переменные, которых не было на платформе

ПеременнаяЧто в ней
LOCAL_STORAGE_DIRПапка для файлов: /var/www/trindelka/files
PUBLIC_FILES_URLПубличный адрес этой папки: https://ваш-домен/files
SEND_MESSAGE_URLВнутренний адрес отправки сообщений: http://127.0.0.1:8000/api/send-message. Через него функции будят отправку запланированных сообщений

Файл /etc/trindelka.env хранит все пароли. Права на него — 600, не копируйте его в папку сайта и в GitHub. Ключ Firebase даёт полный доступ к отправке уведомлений от вашего имени: никому его не отправляйте, а если он утёк, удалите ключ в консоли Firebase и создайте новый.

6. Проверка после запуска

Пройдите по списку на новом адресе, лучше с телефона и с компьютера.

  • https://ваш-домен/api/health показывает status: ok.
  • Главная страница открывается, замок в адресной строке закрыт. Любой несуществующий адрес показывает страницу «не найдено».
  • Регистрация нового аккаунта и вход работают. Мессенджер открывается по адресу /app.
  • «Забыли пароль?» присылает письмо, а ссылка из письма открывает форму нового пароля (проверяет SMTP и адрес /reset-password).
  • Через поиск находится второй аккаунт, создаётся чат, сообщения уходят в обе стороны.
  • Смена фото профиля работает и аватар виден после обновления страницы (проверяет папку файлов и PUBLIC_FILES_URL).
  • Фото и документ отправляются. Свой набор стикеров создаётся и стикеры отправляются.
  • Сообщение, запланированное на 2–3 минуты вперёд, приходит само (проверяет минутный таймер).
  • Опрос создаётся, закрепляется сверху, пересылается в другую группу, ссылка на него открывается.
  • Тихие часы сохраняются после обновления страницы.

Старые ссылки на poehali.dev не отключайте, пока не убедитесь, что всё перенесено.

7. Обновление и резервные копии

Как обновить после новых правок

cd /var/www/trindelka/app
git checkout -- src/platform
git pull
sh deploy/prepare-selfhost.sh
npm install
VITE_API_BASE=/api npm run build
systemctl restart trindelka trindelka-web

Если появились новые файлы в db_migrations (номер больше последнего применённого), примените только их тем же способом: export PGOPTIONS="-c search_path=$SCHEMA", затем psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f db_migrations/ИМЯ_ФАЙЛА.sql. Имя схемы возьмите командой из раздела 3, шаг 5.

Ночная резервная копия

Таймер trindelka-backup.timer, который вы включили в разделе 3, каждую ночь около 03:30 сохраняет базу и папку файлов в /var/backups/trindelka и хранит копии 14 дней. Запуск вручную: sh /var/www/trindelka/app/deploy/backup.sh. Если задать в /etc/trindelka.env переменную BACKUP_PASSPHRASE, копия шифруется, и вместе с ней сохраняется файл настроек. Если задать BACKUP_REMOTE (например, user@другой-сервер:/backups/), копия уходит на другой сервер.

Восстановление

systemctl stop trindelka
sh /var/www/trindelka/app/deploy/restore.sh /var/backups/trindelka/trindelka-ДАТА.tar
systemctl start trindelka
Копия на том же сервере не спасёт при его потере. Периодически копируйте /var/backups/trindelka на другой компьютер или в облако.

8. Уведомления, звонки и Firebase

Уведомления в браузере

Ключи для уведомлений сервер создаёт сам при первом запуске и хранит в таблице app_settings. Если вы переносили базу выгрузкой, они переехали вместе с ней. Включает уведомления каждый человек сам: Профиль → Уведомления → «Уведомления на устройстве». На iPhone сначала нужно добавить сайт на экран «Домой» и открыть его оттуда (iOS 16.4 и новее). Серверу нужен выход в интернет на порт 443.

В «Тихих часах» (там же) уведомления приходят без звука и вибрации. Время считается по часам телефона или компьютера человека.

Звонки

Личные звонки (голос и видео) и групповые идут напрямую между участниками, сервер только соединяет их. Обычно хватает бесплатных серверов Google. Если у кого-то строгий роутер или мобильная сеть с закрытыми соединениями, звонок может не соединиться: тогда нужен свой TURN-сервер (например, coturn на VPS). Впишите в /etc/trindelka.env:

TURN_URL=turn:ваш-домен:3478,turns:ваш-домен:5349
TURN_USER=логин
TURN_PASSWORD=пароль

Firebase и Android

Уведомления в Android-приложении идут через Firebase. Нужно создать бесплатный проект на console.firebase.google.com, добавить Android-приложение с именем пакета ru.trindelka.messenger, затем в «Настройки проекта → Сервисные аккаунты» создать закрытый ключ и вставить весь JSON одной строкой в FIREBASE_SERVICE_ACCOUNT.

Как собрать само приложение, описано в разделе 9.

9. Приложение для Android (APK)

В проекте снова есть папка android с готовым приложением «Трынделка» (пакет ru.trindelka.messenger). Оно работает как «окно» в ваш сайт: открывает ваш адрес https://ваш-домен/app внутри оболочки Android. Поэтому сайт на VPS (раздел 3) должен быть уже запущен и работать по HTTPS. Внутри приложения работают уведомления через Firebase, звонки поверх экрана блокировки, запись голоса и видеокружков.

Что не провереноСборка на этой платформе невозможна, там нет Android SDK. APK собирается один раз на вашем компьютере. Мне самому собрать и проверить его на телефоне не удалось, поэтому после установки пройдите короткую проверку в конце раздела.

Что понадобится

  • Компьютер с Windows, macOS или Linux.
  • Node.js 22 или новее (nodejs.org) и Git.
  • Android Studio (developer.android.com/studio). При первом запуске она сама скачает Android SDK и Java.
  • Работающий сайт на вашем домене по HTTPS.

Шаги

  1. Скачайте код и установите зависимости 
    git clone https://github.com/ВАШ_АККАУНТ/ВАШ_РЕПОЗИТОРИЙ.git trindelka
cd trindelka
npm install
  2. Подключите Firebase для уведомлений

    Один раз создайте бесплатный проект в Firebase (подробности в разделе 8). Затем в консоли Firebase добавьте Android-приложение с именем пакета ru.trindelka.messenger, скачайте файл google-services.json и положите его в папку android/app/ рядом с файлом build.gradle. Без этого файла приложение соберётся и будет работать, но уведомления при закрытом приложении приходить не будут.

  3. Синхронизируйте проект с вашим сайтом 
    ANDROID_SITE_URL=https://ваш-домен npm run android:sync

    Команда записывает адрес вашего сайта в настройки приложения и обновляет папку android. Адрес нужен полный, с https://, без /app на конце. В Windows PowerShell вместо этого выполните две команды: $env:ANDROID_SITE_URL="https://ваш-домен", затем npm run android:sync.

  4. Соберите APK

    Вариант А, через Android Studio. Откройте папку android (File → Open), дождитесь окончания синхронизации и выберите Build → Build Bundle(s) / APK(s) → Build APK(s). Файл появится в android/app/build/outputs/apk/debug/app-debug.apk.

    Вариант Б, командой (нужны Android Studio и Java 21):

    ANDROID_SITE_URL=https://ваш-домен npm run android:apk
  5. Установите на телефон

    Передайте app-debug.apk на телефон кабелем или через облако, откройте его и разрешите установку из неизвестных источников. Это отладочная сборка: она работает как обычное приложение, но не подходит для Google Play и RuStore.

  6. Для магазинов приложений

    В Android Studio: Build → Generate Signed Bundle / APK. Создайте ключ подписи и сохраните файл ключа и пароль в надёжном месте: без них нельзя будет выпускать обновления. RuStore принимает APK, Google Play требует формат AAB (в том же меню).

Что настроено в приложении

  • Уведомления о сообщениях приходят через Firebase даже при закрытом приложении. Для тихих часов создан отдельный бесшумный канал.
  • Звонки. Входящий звонок показывается поверх экрана блокировки с кнопками «Принять» и «Отклонить». На Android 14 разрешение «звонки на весь экран» нужно включить один раз: Профиль → Уведомления → «Разрешить».
  • Права: интернет, уведомления, микрофон и камера (для голосовых, кружков и звонков).
  • Вход. Сессия хранится в приложении, повторно входить не нужно.
  • Без сети. Если сайт недоступен, приложение показывает страницу «Нет соединения с сервером».

Короткая проверка после установки

  • Приложение открывается и показывает экран входа вашего сайта.
  • Вход работает, сообщения отправляются и приходят.
  • Профиль → Уведомления → включить «Уведомления на устройстве»; закройте приложение и отправьте себе сообщение с другого аккаунта: должно прийти уведомление.
  • Позвоните с другого аккаунта: звонок появляется с кнопками «Принять» и «Отклонить».
  • Запишите голосовое сообщение и видеокружок: проверьте, что приложение просит доступ к микрофону и камере.
ОбновленияЛюбые правки сайта (новые функции, дизайн) попадают в приложение сразу после обновления сайта на сервере: пересобирать APK не нужно. Пересобирать его нужно только при смене домена или значка, либо при замене файла google-services.json.

10. Что умеет мессенджер

Список в том порядке, в котором функции появлялись в мессенджере. Всё перечисленное уже работает, кроме отмеченных оговорок.

  1. Вход и профиль. Регистрация и вход по почте и паролю. Вход держится 6 месяцев. Восстановление пароля по письму. Профиль: логин, имя, фамилия, фото, «настроение» (эмодзи и короткая фраза) и «о себе».
  2. Личные чаты. Поиск человека по нику, имени или фамилии и переписка один на один. Закрепление чатов вверху списка. Выключатель уведомлений для каждого чата.
  3. Группы. Создание групп с названием, фото и описанием. Роли: владелец, администратор, участник. Добавление и удаление людей, передача владения, выход из группы.
  4. Темы в группах. Внутри группы можно создавать темы (отдельные ветки разговора) и закреплять важные.
  5. Текст и ответы. Отправка текста, ответ на конкретное сообщение, обычные эмодзи, ссылки.
  6. Изменение отправленного сообщения. Свои текстовые сообщения, фото и файлы с подписью можно исправить: правый клик → «Изменить», кнопка-карандаш рядом с сообщением или стрелка вверх в пустом поле ввода. Появляется пометка «изменено». Опрос, стикер и GIF изменить нельзя.
  7. Удаление. Своё сообщение удаляется у всех (остаётся пометка «сообщение удалено»). Чужое сообщение можно удалить только у себя: у отправителя оно сохраняется.
  8. Пересылка. Пересылка одного сообщения в любой чат или группу с пометкой «переслано от».
  9. Выбор нескольких сообщений. Кнопка-галочка в шапке чата, пункт «Выбрать» в меню сообщения или долгое нажатие на телефоне включают отметки. Выбранные сообщения можно сразу переслать или удалить.
  10. Меню по правому клику. Все действия с сообщением собраны в одном меню: правый клик по сообщению (на телефоне долгое нажатие) открывает реакции, ответить, копировать, изменить, переслать, закрепить, выбрать, удалить.
  11. Реакции. Быстрые эмодзи-реакции на сообщения.
  12. Закрепление сообщения. Любое сообщение можно закрепить сверху чата. Если закрепить опрос, он остаётся сверху с результатами в процентах, и за него можно голосовать без прокрутки.
  13. Поиск в переписке. Лупа в шапке чата ищет слово в открытом чате, подсвечивает совпадения и листает их.
  14. Общий поиск. Вкладка «Поиск» → «Сообщения» ищет по всем вашим чатам и группам. Есть фильтры: по чату, по отправителю и по датам. Слово подсвечивается, клик по результату открывает чат на нужном сообщении.
  15. Фото и файлы. Отправка фото и документов (до 8 МБ), в том числе перетаскиванием в окно и вставкой из буфера обмена (Ctrl+V).
  16. Голосовые и кружки. Запись голосовых сообщений и видеокружков. Голосовое можно расшифровать в текст (нужен ключ OpenAI).
  17. GIF. Встроенный набор из 72 анимированных GIF на все случаи жизни (приветствия, смех, реакции, любовь, праздник, работа, настроение), они лежат в самом сайте и работают без интернета-сервисов. Живой поиск по большой библиотеке включается ключом Klipy.
  18. Стикеры. Готовые современные 3D-наборы (эмоции, жесты, любовь, праздник, зверята, еда, дела, настроение, всего 128 стикеров), избранные стикеры и свои наборы из загруженных картинок: создать набор, добавить и удалить картинки, отправлять так же, как готовые.
  19. Опросы. Опросы в группах: один или несколько вариантов, результаты в процентах, кто как проголосовал, завершение опроса автором или администратором.
  20. Пересылка опроса и ссылка. Опрос можно переслать в другую группу (голоса общие) или скопировать ссылку: по ней голосуют и те, кто не состоит в исходной группе.
  21. Отложенная отправка. Часы рядом с кнопкой отправки: выбрать дату и время, и сообщение уйдёт само. Можно планировать текст, фото, файлы и стикеры. Над полем ввода список запланированного: каждое сообщение можно изменить (текст и время) или отменить.
  22. Черновики. Набранный, но не отправленный текст сохраняется отдельно для каждого чата и темы и возвращается после закрытия или сбоя.
  23. Статусы и галочки. «В сети», «был(а) недавно», «печатает…», доставлено и прочитано. В группах видно, сколько человек прочитало, и можно открыть список «кто прочитал».
  24. Приватность. Можно скрыть статус «в сети», индикатор «печатает», галочки прочтения и ограничить, кто может писать вам первым (все или только контакты).
  25. Уведомления. Уведомления на устройстве (даже при закрытом сайте), «колокольчик» внутри приложения, звук, выключатель для каждого чата.
  26. Тихие часы. Время «с / до» (например, 23:00–8:00): в эти часы сообщения приходят без звука и вибрации.
  27. Звонки. Голосовые и видеозвонки один на один, а также групповые звонки в группах. Входящий звонок показывается поверх экрана.
  28. Фон чата. Для каждого чата свой фон: готовые, однотонный цвет или своя картинка.
  29. Оформление. Тёмная, светлая или системная тема, цветовой акцент, размер текста.
  30. Боты. Магазин демонстрационных ботов (в том числе игра «Крокодил»). Они отвечают заготовленными фразами на самом сайте и не связаны с серверными функциями.
  31. Папки чатов. Над списком чатов вкладки «Все», а рядом свои папки, например «Работа», «Семья», «Друзья». Кнопка «+» создаёт папку (до 12), правый клик по вкладке или карандаш переименовывает и удаляет. Чат переносится в папку значком папки в строке чата. Папки личные: у каждого человека свои. При удалении папки чаты не пропадают, а остаются во вкладке «Все».
  32. Упоминания в группах. В группе набор @ открывает список участников с подсказкой: выбирать можно стрелками и Enter либо касанием. Упоминание подсвечивается в тексте, а упомянутому человеку приходит отдельное уведомление «упомянул(а) вас», даже если уведомления этой группы у него выключены. В тихие часы это уведомление приходит без звука.
  33. Кнопка отправки. Кнопка со стрелкой всегда рядом с полем ввода. На телефоне это удобнее, чем Enter.
  34. Меню сообщения на телефоне. Обычное касание по сообщению открывает то же меню, что правый клик на компьютере. Касания по ссылкам, фото, видео и кнопкам работают как раньше.
  35. Галерея. Вкладка собирает все фото и видео из ваших чатов (GIF в неё не попадают). Есть фильтры по типу файла и по чату, просмотр на весь экран с перелистыванием и кнопкой «В чат», которая открывает исходное сообщение.
